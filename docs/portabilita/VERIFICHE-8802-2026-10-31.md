## Verifiche del definitivo

Lo script di esportazione controlla integrità CRC, presenza dei file indispensabili, corrispondenza SHA-256 di ogni file col commit finale ed esclusione di `.env` reali, chiavi riconoscibili, database runtime, `.git`, `node_modules`, `dist`, cache e log. Lo ZIP conserva la cartella sorgente unica `latino-facile-app/`; per GitHub il suo contenuto deve essere nella radice della repository.

Il JSON esterno `.verifica.json` riporta il numero finale di file/link, l'elenco e gli hash per file, i confronti con il codice pubblicato e la ricostruzione isolata. Il file `.sha256` identifica lo ZIP finale, non la vecchia build o il candidato.

## Note sul collaudo e limiti

Durante il collaudo si sono corretti solo problemi del verificatore esterno: lettura dei codici ANSI del riepilogo dei test, disponibilità di memoria dopo la chiusura di server locali duplicati e uso esplicito di `NODE_ENV=production` per la build anziché ereditare l'ambiente test. I controlli già riusciti sono stati riutilizzati; i log originali e la sequenza dei controlli restano nel rapporto della ricostruzione. **Nessuna correzione al codice dell'app è stata necessaria.**

Non sono stati effettuati un nuovo deploy Render, un vero `docker build/run` o una nuova campagna browser/mobile per questo export. Le guide includono Blueprint e Dockerfile, ma l'avvio locale non certifica una pubblicazione remota. I test ripetuti qui non misurano l'accuratezza grammaticale/OCR o l'efficacia per tutti gli studenti BES. La campagna UI documentata per il rilascio usava API simulate e touch emulato; non è un test su telefono fisico. I PDF campione non sono taggati e non si dichiara conformità PDF/UA o WCAG. La scansione delle firme note dei segreti non è un audit di sicurezza completo. Rimane l'avviso di build sui chunk JavaScript grandi.
