## 0. Accessibilità (LEGGI PRIMA)

Questa app è **accessibile per la didattica inclusiva** (DSA/BES, ipovisione): il font **OpenDyslexic** è il font principale di tutta l'interfaccia, e la barra di accessibilità (dimensione testo 80–160%, interlinea 1.65–2.6, righello di lettura, alto contrasto, lettura ad alta voce Ascolto → Leggi) è visibile su ogni pagina. **Il documento [`ACCESSIBILITA.md`](ACCESSIBILITA.md) ricapitola TUTTE le misure** (font, barra, focus da tastiera, `prefers-reduced-motion`, lettura ad alta voce, PDF in OpenDyslexic, embed accessibile) e spiega come riusarle su altre app: copialo insieme a `AccessibilityContext.tsx`, `AccessibilityToolbar.tsx`, `useReadAloud.ts` (lettura ad alta voce), la cartella `client/public/fonts/` e le regole CSS indicate — sono il «pacchetto accessibilità» riutilizzabile.

> ⚠️ Durante la ricostruzione NON rimuovere: i `@font-face` di OpenDyslexic in `client/src/index.css`, la barra di accessibilità, le variabili CSS `--lf-scale`/`--lf-lh`, le classi `lf-ruler`/`lf-hc`, il blocco CORS `/fonts` in `server/_core/index.ts` e la sincronizzazione altezza embed (`heightSync.ts`). Sono parte integrante dell'app.

## 1. Che cos'è questa app

Applicazione web didattica che colora le frasi latine parola per parola:

- L'utente scrive (o carica tramite OCR) una o più frasi in latino.
- Il server le analizza con il motore **Whitaker's Words**, arricchito da un glossario italiano personalizzato.
- Ogni parola viene colorata in base alla categoria grammaticale e mostrata grande e in grassetto (le parole NON vanno dentro riquadri colorati).
- Toccando una parola si vedono tutte le analisi possibili e si può cambiare il colore.
- L'utente può scaricare il PDF della frase colorata (parole grandi, in grassetto, lettere colorate, una frase per riga, **senza intestazione**).
- Un pulsante **MOSTRA/NASCONDI TRADUZIONE** mostra la traduzione in italiano (IA se disponibile, altrimenti glossario parola per parola).
- Interfaccia in font **OpenDyslexic** ad alta leggibilità (fallback Cambria/Times New Roman/Georgia) — vedi [`ACCESSIBILITA.md`](ACCESSIBILITA.md).
- **Nessun footer**: la pagina termina con l'area di lavoro. In alto, header con titolo **"LATINO FACILE"** centrato e la barra di accessibilità **bianca** (FONT/INTERLINEA/RIGHELLO/MODALITÀ/ASCOLTO) sopra la fascia header uniforme color carta `#f8f1e4`. **Nessun pulsante al quaderno nell'header**: i pulsanti "IL QUADERNO PDF" e la costante `PDF_LINK` sono stati RIMOSSI da `Home.tsx` (i PDF del quaderno restano solo come asset storici in `client/public/`). NON reintrodurli senza richiesta esplicita dell'utente.

## 2. Passi di ricostruzione

```bash
# 1) Ottieni il codice
git clone <URL-repository> && cd latino-facile-app
# oppure: estrai lo ZIP nella cartella latino-facile-app/

# 2) Installa le dipendenze (il lockfile garantisce versioni identiche)
pnpm install --frozen-lockfile

# 3) Crea le variabili d'ambiente
cp .env.example .env
# ⚠️ POI inserisci la chiave reale: EASY_PEASY_API_KEY=... (e DEEPL_API_KEY=...)
#    Senza chiave l'app NON dà errori: SILENZIOSAMENTE ricade su traduzione
#    MyMemory + colorazione «regole» (incidente del 25/10/2026: ricostruzione
#    da GitHub senza ripristino del .env → l'utente ha perso l'IA per giorni).
#    Verifica rapida dopo l'avvio:
#    curl -s -X POST "http://localhost:3000/api/trpc/latino.translate?batch=1" \
#      -H "Content-Type: application/json" \
#      -d '{"0":{"json":{"text":"Puella ancillam amat."}}}' | grep -o 'colorSource":"[a-z]*'
#    → deve restituire "colorSource":"ai" (se restituisce "regole" la chiave
#      manca o è scaduta). Nota: `tsx watch` NON ricarica il .env modificato:
#      dopo averlo creato/cambiato riavvia davvero il processo (pkill del
#      server + `pnpm dev` di nuovo).

# 4) Avvia il server di sviluppo
pnpm dev
# → l'app è su http://localhost:3000
```

**Verifiche di qualità:**

```bash
pnpm check      # type-check TypeScript (tsc --noEmit) → deve dare 0 errori
pnpm test       # test unitari (vitest)
```

**Produzione:**

```bash
pnpm build      # compila client (vite) + server (esbuild) in dist/
pnpm start      # NODE_ENV=production node dist/index.js
```

## 5. Comportamenti da replicare ESATTAMENTE (punti di personalizzazione)

1. **Font**: tutto il testo usa lo stack `"OpenDyslexic", "Cambria", "Times New Roman", Georgia, serif` (classi `font-display` in `index.css`). **OpenDyslexic è il font PRINCIPALE** (misura di accessibilità — vedi `ACCESSIBILITA.md` §2.1): non cambiarlo né rimuoverlo.
2. **Header e footer**: l'app **NON ha footer** (nessun "REALIZZATO DA…" in fondo) e **NON ha più l'header con il titolo** "LATINO FACILE" (rimosso da `Home.tsx` su richiesta esplicita dell'utente, 26/10: la pagina `/app` inizia direttamente con la card di input; il titolo resta solo in `WelcomePage.tsx` e nel `<title>`); la barra di accessibilità è **bianco caldo `#fdfbf8`** con capsule crema `#f5f0e6` (come da foto di riferimento: bordi `#dedbd6`, testo `#2e2118`, pulsanti trasparenti senza pillole bianche) sopra lo sfondo della pagina (`#f8f1e4`).
3. **Limite input**: `MAX_CHARS = 400` (costante esportata in `Home.tsx`, riga ~267). Applicata sia al textarea (`maxLength`) sia al testo riconosciuto dall'OCR (che viene troncato a 400 caratteri).
4. **Colori delle categorie**: la legenda e i colori sono definiti in `LEGEND_ITEMS` (`shared/types.ts`, riga ~151): **fonte unica** da cui derivano IDENTICHE la legenda dell'app (`Home.tsx`) e quella del PDF (`export.ts`). 12 voci (SCONOSCIUTO non compare più in legenda; la categoria grigia resta per l'analisi), 3 righe per voce: `label` (caso/modo) → `compl` (testo esplicativo nel colore CHIARO del caso via `lightenColor()`: SOGGETTO, COMPLEMENTO DI SPECIFICAZIONE / DI TERMINE / OGGETTO / DI VOCAZIONE, MEZZO · MODO · CAUSA · LUOGO · TEMPO, PREDICATO VERBALE, **PAROLE DI SERVIZIO** per AVVERBI/PREPOSIZIONI/CONGIUNZIONI) → `sub` (domanda in corsivo o esempi `NUNC = ora · AD = a · ET = e`). Sotto la griglia una **nota sulla voce verbale COLORATA** (`LEGEND_VOICE_NOTE`, parti con `underline` disegnate davvero sottolineate e con `color` per il colore del testo): «IL PREDICATO VERBALE SOTTOLINEATO = VOCE PASSIVA - IL PREDICATO VERBALE NON SOTTOLINEATO = VOCE ATTIVA» — la parte della **VOCE PASSIVA è in ROSSO `#C62828`** (`VOICE_PASSIVE_COLOR`, incluso il SOTTOLINEATO sottolineato) e la parte della **VOCE ATTIVA in VERDE `#2E7D32`** (`VOICE_ACTIVE_COLOR`); il separatore « - » resta nel colore standard `#2e2018`; sottolineatura SOLO sul primo SOTTOLINEATO; identica in APP e PDF (nel PDF il font della nota si restringe per entrare nei margini e usa `part.color ?? "#2e2018"`) e, sotto, i casi della griglia portano `numero: true` e diventano DUE voci: «CASO SINGOLARE» con la sfumatura chiara e «CASO PLURALE» con quella scura (due quadratini, stessa riga), identiche in app e PDF. Ogni **parola declinabile** (nome, aggettivo, pronome, numerale — `DECLINABILI`/`numeroPerSfumatura` in `shared/types.ts`) distingue il numero con la **SFUMATURA del colore** (`TokenAnalysis.number` → `shadeForNumber`): **più CHIARA = singolare, più SCURA = plurale** dello stesso colore di base — nei chips dell'app, nel PDF (lettere colorate) e nelle voci della legenda; verbi e invariabili restano del colore pieno. Il numero resta nei dati per distinguere le opzioni con lo stesso caso (es. «currus»). Il colore scelto a mano (`coloreFinale` in `ExportToken`) è FINALE: nessuna sfumatura sopra. La **palette del cambio colore** (`COLOR_PALETTE` in `Home.tsx`) è DERIVATA da `LEGEND_ITEMS` con `shadeForNumber` (le due sfumature per ogni caso + indicativo, congiuntivo, altri modi, avverbi, preposizioni, congiunzioni, — nessuna voce extra: il dialogo offre esattamente i colori della legenda): palette e legenda restano identiche per costruzione. L'evidenziazione del colore corrente è PER VOCE, non per colore: `vocePerAnalisi` (dall'analisi grammaticale) o l'ultima voce scelta a mano (`overrideVoci`), così solo la categoria scelta si evidenzia, indipendentemente dalla tinta. La nota generica sul numero non esiste più: le due voci per caso sono autoesplicative. INDICATIVO è **arancione `#EF6C00`** (distinto dal rosso del nominativo); CONGIUNTIVO è **magenta `#AD1457`** (distinto dall'indaco `#3949AB` del VOCATIVO); AVVERBI **blu intenso `#0057D9`**, PREPOSIZIONI **grigio chiaro `#BDBDBD`**, CONGIUNZIONI **grigio scuro `#4A4A4A`**, con compl «PAROLE DI SERVIZIO» ed esempi rispettivi; la voce ALTRI MODI VERBALI (marrone #795548) porta `compl` PREDICATO VERBALE.
5. **PDF esportato** (`export.ts`): ogni parola è disegnata **grande, in grassetto, con il colore della categoria** (`font: bold`, testo colorato) — **MAI** dentro riquadri/rettangoli colorati. I verbi **passivi** (`voice: "passivo"` su `ExportToken`, dall'analisi morfologica) sono **SOTTOLINEATI** con una linea nello stesso colore della parola (come i chip nell'app). Una frase per riga. **Nessuna intestazione** (le scritte "LATINO FACILE — FRASE COLORATA" e "REALIZZATO DA ANDREA CENTINARO" NON devono comparire nel PDF).
6. **Traduzione e colorazione IA** (`routers.ts` → `latino.translate` / `recolor`) — **26/10c: SOTTOLINEA LA PAROLA in FONDO allo specchietto del colore** (dopo la griglia, non sopra); **IA FUNZIONANTE e prioritaria** (verifica 26/10: FRASE LATINA vera: source: ai + colorSource: ai con Piratarum genitivo pl. / Minotaurum accusativo / totidemque accusativo con QUE grigio; stessa frase in produzione: identico risultato; la stringa italiana 'La fanciulla ama l ancella.' va in auto/regole PERCHÉ NON È LATINO — non è un bug. Sequenza chiamate translate: (1) verifyWithAI traduzione+ruoli 35s → (2) se mancano i ruoli, assignRolesWithAI 20s → (3) DeepL/MyMemory/glossario + verifica IA 30s + fallback ruoli 20s. L'opzione generica sintetizzata colora PIRATARUM/MINOTAURUM/TOTIDEMQUE col caso IA o desinenze); **26/10b: MAX_PAROLE = 50** (`Home.tsx`); **sottolineatura manuale** (nel dialog colore di ogni parola il pulsante SOTTOLINEA LA PAROLA / TOGLI LA SOTTOLINEATURA — `underlineOverrides` in `Home.tsx`, vincono sulla voce dell'analisi anche nel PDF); **fallback DESINENZE** (`guessFromEnding` in `translationColors.ts`: parole sconosciute a Whitaker E all'IA colorate dalla desinenza — -arum/-orum → genitivo plurale, -um/-am/-em → accusativo, -os/-as → accusativo plurale, -ibus → ablativo plurale, -us/-a → nominativo — con divisione dell'enclitica attaccata, es. TOTIDEMQUE; le parole intere atque/neque/itaque/denique/quoque NON vengono divise); opzione generica sintetizzata per OGNI parola sconosciuta con ruolo (IA o desinenze) invece di restare bianca; — **26/10: parole non riconosciute = CHIP BIANCO con SCRIITTA NERA** (`POS_COLORS.sconosciuto = #FFFFFF` + `UNKNOWN_TEXT_COLOR = #1a1a1a` in `shared/types.ts`; nel PDF, dove le lettere sono colorate senza sfondo, queste parole si disegnano in nero perché lettere bianche su pagina bianca sarebbero invisibili), **enclitiche** (es. TUTAMQUE = TUTAM + QUE: il JSON IA include l'oggetto opzionale `enclitiche` `{"tutamque": {"base": "accusativo", "enclitica": "congiunzione"}}`; `applyRoleOverrides` assegna alla parola il caso della BASE (con opzione generica sintetizzata se Whitaker non la conosce) e le lettere del suffisso prendono il PROPRIO colore (`TokenAnalysis.suffisso`: QUE grigio ardesia #455A64 delle congiunzioni, CUM grigio delle preposizioni — sfondo del chip interamente del caso della base, nel PDF le lettere si disegnano in due segmenti) e **regole di precisione nel prompt** (nomi propri con SEMPRE un caso dedotto da desinenza/contesto, aggettivi/pronomi/numerali SEMPRE concordi con il nome): l'IA usa `generateText` (`server/_core/llm.ts`). I template `/api/generate` (preset `custom-generator`) possono andare in **quota token (401)**; in quel caso `generateText` passa automaticamente a **chat Gemini** (`server/_core/chat.ts`, `gemini-3-flash`, stessa `EASY_PEASY_API_KEY`). Se anche la chat fallisce (chiave assente) si usa DeepL → MyMemory → glossario. La colorazione IA (`assignRolesWithAI` / `verifyWithAI`) segue lo stesso canale. **Le frasi sono processate a CHUNK di 2 con chiamate parallele (ondate di 4) e output «Long»** (`verifyAI.ts`): in una sola chiamata il JSON superava max_tokens («Medium» = 800 token), si troncava e con più frasi la colorazione restava «regole» pur avendo risposto l'IA. Cache in memoria per chunk (si rifanno solo i chunk falliti); fallback «solo ruoli» (20 s) quando il JSON combinato traduzioni+ruoli non contiene ruoli validi. Timeout: primo giro IA 35 s, verifica post-percorso-automatico e `recolor` 30 s. Le risposte IA includono anche i **numeri** (`numeri`: singolare/plurale per parola) per l'apice S/P; `applyRoleOverrides` usa il numero per scegliere l'opzione giusta quando lo stesso caso esiste in entrambi i numeri (es. «currus» nominativo singolare E plurale). Senza questa fallback l'app resta su «Colorazione con regole» / «Traduzione automatica» anche con la chiave presente.**26/10d** — (1) Banner «Parole non riconosciute» ELIMINATO per sempre (nessun caso lo mostra più): le parole non riconosciute restano chip BIANCO con scritta nera. (2) Nuova nota sotto la legenda voce (UI e PDF): «Le parole non riconosciute dall'IA sono contrassegnate dal colore bianco» (nel PDF con quadratino bianco bordato). (3) Enclitiche col colore OPPORTO alla parola principale (26/10): principale bianca → enclitica NERA; principale scura → enclitica BIANCA; nel PDF le lettere sono colorate su pagina bianca quindi base CHIARA → enclitica nera, base scura → enclitica grigio ardesia (enclDrawColor in export.ts). Sicurezza: su chip bianco (parola sconosciuta) l'enclitica resta scura. ## 7. Deploy su Render (guida completa)

Render è la piattaforma consigliata: la repository include il Blueprint `render.yaml`, quindi il deploy avviene con un clic.

### 7.1 Deploy con Blueprint (consigliato)

1. Carica il progetto su GitHub: crea una repository vuota, poi dalla cartella del progetto:

   ```bash
   git init && git add . && git commit -m "Latino Facile"
   git branch -M main
   git remote add origin https://github.com/<TUO-UTENTE>/latino-facile-app.git
   git push -u origin main
   ```

2. Su [render.com](https://render.com) (account gratuito) scegli **New → Blueprint**.
3. Collega la repository: Render legge `render.yaml` e crea il Web Service con:
   - build command: `pnpm install --frozen-lockfile && pnpm build`
   - start command: `pnpm start`
   - health check path: `/_health`
   - Node.js 22 (`NODE_VERSION`), `BETTER_AUTH_SECRET` generata automaticamente
4. Dopo il primo deploy: apri il servizio → **Environment**, imposta `TRUSTED_ORIGINS` col dominio (es. `https://latino-facile.onrender.com`) e, se vuoi, `EASY_PEASY_API_KEY` e/o `DEEPL_API_KEY`. Salva (Render riavvia da solo).

| Campo | Valore |

### 7.3 Note tecniche per Render

- **Porta**: Render imposta `PORT` automaticamente; `server/_core/index.ts` ascolta su `0.0.0.0:${PORT}` in produzione (niente porta fissa da configurare).
- **pnpm**: Render abilita corepack leggendo `packageManager` in `package.json` → `pnpm@10.4.1`. Il lockfile garantisce installazioni identiche; la patch `patches/wouter@3.7.1.patch` viene applicata automaticamente da pnpm.
- **Build scripts**: `onlyBuiltDependencies` in `package.json` autorizza i postinstall di `esbuild`, `@tailwindcss/oxide`, `tesseract.js`, `@swc/core`, `sharp`: senza questo il build fallirebbe. NON rimuoverli.
- **Database**: non serve per le funzioni principali. Per auth e traduzione IA puoi aggiungere un'istanza PostgreSQL (Render o Neon) e impostare `DATABASE_URL`; `drizzle/schema.ts` contiene lo schema, le migrazioni sono in `drizzle/` (da applicare con `pnpm db:push` se usi il database).
- **OCR e font**: `client/public/tessdata/lat.traineddata.gz` e `client/public/fonts/OpenDyslexic-*.{ttf,otf,woff2}` sono serviti staticamente insieme all'app: nessuna configurazione extra. Il PDF esportato incorpora gli stessi OpenDyslexic (`export.ts`), quindi non servono font PDF separati.
- **Quaderno PDF**: i pulsanti "IL QUADERNO PDF" e la costante `PDF_LINK` NON esistono più in `Home.tsx` (rimossi): i file `quaderno-unico-v*.pdf` in `client/public/` sono asset storici senza link nell'app. NON reintrodurre pulsanti/link al quaderno senza richiesta esplicita dell'utente.

### 7.4 Altre piattaforme

Stesso comando di avvio (`pnpm start`) su **Railway**, **Google Cloud Run** (endpoint `/_health` già presente) e **qualsiasi VPS**. Build: `pnpm install --frozen-lockfile && pnpm build`.

### 7.5 CI automatica (GitHub Actions)

La repository include `.github/workflows/ci.yml`: a ogni push o pull request verso `main`/`master` esegue `pnpm install --frozen-lockfile`, `pnpm check`, test unitari (`vitest run --passWithNoTests`) e `pnpm build`, e salva `dist/` come artefatto scaricabile (7 giorni). Il workflow usa Node.js 22 e pnpm 10.4.1 (stesse versioni di sviluppo).
